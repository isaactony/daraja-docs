title: "Error codes"
description: "Daraja errorCode values such as 500.001.1001, 404.001.03, and 400.002.02: what each one means, the likely cause, and the fix, from the official API pages."
---

An **error code** (`errorCode`) means Daraja rejected your request. Nothing reached the customer. Errors come back immediately, with an HTTP error status and a body like this:

```json
{
  "requestId": "1c5b-4ba8-815c-ac45c57a3db01495926",
  "errorCode": "400.002.02",
  "errorMessage": "Bad Request - Invalid BusinessShortCode"
}
```

The same `errorCode` can carry different messages, so always read `errorMessage` too. Keep the `requestId` for support requests.

| `errorCode` | `errorMessage` | Cause and fix |
| :-- | :-- | :-- |
| `400.008.01` | Invalid authentication type passed. The sandbox's actual message is "Invalid Authentication passed". | The token request didn't use Basic authentication. See [Get an access token](/guides/get-an-access-token). |
| `400.008.02` | Invalid grant type passed | Add `grant_type=client_credentials` to the token URL. |
| `404.001.03` | Invalid Access Token | The token is wrong, expired, or replaced by a newer one. See [the fix](/troubleshooting/invalid-access-token). |
| `400.003.01` | Invalid Access Token | The C2B page's code for the same problem. |
| `404.001.04` | Invalid Authenticator Header. The sandbox's actual message is "Invalid Authentication Header". | Missing or misplaced `Authorization` header. The sandbox returns it when the header is missing entirely. |
| `400.002.02` | Bad Request - Invalid *Field* | A field is missing or has the wrong format. The message names it. See [the fix](/troubleshooting/bad-request-invalid). |
| `400.002.05` | Invalid Request Payload | The JSON body is malformed, for example a trailing comma or a typo in a field name. |
| `400.003.02` | Bad Request | Something required is missing from a C2B request. |
| `404.001.01` | Resource not found | Wrong endpoint URL. Check the path and version in [Endpoints](/reference/endpoints). |
| `404.003.01` | Resource not found | Wrong C2B endpoint URL. |
| `405.001` | Method Not Allowed | Use `POST`. Only the token request uses `GET`. In the sandbox, a `GET` to the STK Push endpoint returned `500.002.1001` "Service is temporarily unavailable" instead. |
| `500.001.1001` | Wrong credentials | The STK `Password` doesn't match the shortcode, passkey, and timestamp. See [the fix](/troubleshooting/wrong-credentials). |
| `500.001.1001` | Merchant does not exist | The `BusinessShortCode` isn't the one your app went live with, or isn't valid in this environment. |
| `500.001.1001` | Unable to lock subscriber, a transaction is already in process for the current subscriber | The phone already has an active prompt. See [the fix](/troubleshooting/unable-to-lock-subscriber). |
| `500.001.1001` | The transaction does not Exist | Observed in the sandbox for an STK Query with an unknown `CheckoutRequestID`. Check the ID, and that you're querying the same environment and shortcode. |
| `500.001.1001` | The transaction is being processed | Not in the official tables; reported by developers for an STK Query sent before the customer answers. Treat the payment as pending and query again later. See [Confirm a payment without a callback](/guides/confirm-a-payment-without-a-callback). |
| `500.003.1001` | Urls are already registered. | C2B URLs exist for this production shortcode. See [the fix](/troubleshooting/urls-already-registered). |
| `500.003.1001` | Duplicate notification info, SP ID is ..., correlator is ... | The shortcode has URLs on Safaricom's older aggregator (Broker) platform. Ask Safaricom to delete them first. |
| `500.003.1001` | Internal Server Error | Usually a problem on Safaricom's side, or a malformed request. Check your request, then retry later. |
| `500.003.02` | System is busy. Please try again in few minutes. | Retry after a short wait. |
| `500.003.02` | Error Occurred: Spike Arrest Violation | Too many requests per second, or, for C2B, your endpoints returning many errors. Slow down and fix failing endpoints. |
| `500.003.03` | Error Occurred: Quota Violation | Too many requests overall. |
| `500.002.1001` | Service is temporarily unavailable. Please try again later | Observed in the sandbox for a `GET` request to a `POST` endpoint. It can also mean a real outage, so check your method first. |

## Errors that don't use `errorCode`

Two responses observed in the sandbox on 13 November 2026 have a different shape, so code that only reads `errorCode` misses them:

- **Rate limit (HTTP 429).** The body is a `fault` object:

  ```json
  {
    "fault": {
      "faultstring": "Spike arrest violation. Allowed rate : MessageRate{messagesPerPeriod=30, periodInMicroseconds=60000000, maxBurstMessageCount=3.0}",
      "detail": { "errorcode": "policies.ratelimit.SpikeArrestViolation" }
    }
  }
  ```

  This one allowed 30 requests per minute, with at most 3 in a burst, for STK Query in the sandbox. Production limits may differ.
- **Malformed JSON.** A body with a trailing comma returned HTTP 400 with `{"responseId": "...", "responseCode": "400", "responseDesc": "Duplicate json key detected"}`. The message is misleading: the problem is the JSON syntax.

A wrong consumer key or secret returns HTTP 400 with an **empty** body. Always check the HTTP status before you parse the body.

Sources: the current official Authorization, M-Pesa Express, and C2B pages, and sandbox tests on 13 November 2026. The official pages give the same `errorCode` for different problems and different codes for the same problem, such as two codes for "Invalid Access Token". See [Known doc discrepancies](/reference/known-doc-discrepancies).

## Handle errors in code

- **Retry** only `500.003.02` (busy or spike arrest), with a growing delay.
- **Refresh the token once** on "Invalid Access Token", then retry once.
- **Don't retry** the others. Fix the request.
