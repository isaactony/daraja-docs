The Business to Customer (B2C) API sends money from your business's B2C account to a customer's M-Pesa wallet. Use it for refunds, salaries, loan disbursements, cashback, and winnings.

## Before you begin

- **A B2C-capable account.** In production, you need a bulk disbursement (B2C) shortcode, or a paybill or till converted to a "one account" that can both receive and send. Apply through Safaricom.
- **An initiator and its security credential.** See [Initiators and security credentials](/concepts/initiators-and-security-credentials) and [Encrypt the security credential](/guides/encrypt-the-security-credential).
- **Public `ResultURL` and `QueueTimeOutURL` endpoints.** See [Callbacks](/concepts/callbacks).
- **A separate Daraja app** if your existing app has C2B. One app can't have both.

## Choose the command

| `CommandID` | Use for |
| :-- | :-- |
| `BusinessPayment` | Ordinary payouts to registered M-Pesa customers, such as refunds and cashback |
| `SalaryPayment` | Salaries. The official docs say sending to unregistered numbers is no longer supported. |
| `PromotionPayment` | Promotional payouts, which come with a congratulatory message |

## Send the payment

```http
POST /mpesa/b2c/v3/paymentrequest
```

```json
{
  "OriginatorConversationID": "refund-ord-1042-1",
  "InitiatorName": "testapi",
  "SecurityCredential": "<encrypted initiator password>",
  "CommandID": "BusinessPayment",
  "Amount": 10,
  "PartyA": "600992",
  "PartyB": "254712345678",
  "Remarks": "Refund for order 1042",
  "QueueTimeOutURL": "https://your-domain.example/payments/b2c/timeout",
  "ResultURL": "https://your-domain.example/payments/b2c/result",
  "Occassion": "Refund"
}
```

| Field | Notes |
| :-- | :-- |
| `OriginatorConversationID` | **Your** unique ID for this payout. Generate it, store it before you send, and reuse it to look the payout up. It's how you avoid paying twice. |
| `PartyA` | Your B2C shortcode |
| `PartyB` | The customer's phone, 12 digits |
| `Remarks` | 2 to 100 characters |
| `Occassion` | Optional, 1 to 100 characters. **Spelled with a double "s"** in this API. |

```javascript Node.js
const ack = await b2cPayment({
```


## Handle the result

The outcome arrives at your `ResultURL`. A wrong security credential, for example, is still accepted at first and only fails here.

```json
{
  "Result": {
    "ResultType": 0,
    "ResultCode": 0,
    "ResultDesc": "The service request is processed successfully.",
    "OriginatorConversationID": "53e3-4aa8-9fe0-8fb5e4092cdd3533373",
    "ConversationID": "AG_20240706_2010364430d9bbdaf872",
    "TransactionID": "SG632NMUAB",
    "ResultParameters": {
      "ResultParameter": [
        { "Key": "TransactionAmount", "Value": 10 },
        { "Key": "TransactionReceipt", "Value": "SG632NMUAB" },
        { "Key": "ReceiverPartyPublicName", "Value": "254705912645 - NICHOLAS JOHN SONGOK" },
        { "Key": "TransactionCompletedDateTime", "Value": "06.07.2024 22:48:52" },
        { "Key": "B2CRecipientIsRegisteredCustomer", "Value": "Y" }
      ]
    }
  }
}
```

The official sample has more balance fields, trimmed here. Note:

- `ResultParameters` appears only on success.
- `TransactionCompletedDateTime` is `DD.MM.YYYY HH:mm:ss`, a different format from STK Push's `YYYYMMDDHHmmss`.
- `ReceiverPartyPublicName` gives you the recipient's registered name, useful for confirming you paid the right person.

The tested `parseResult()` function in [`examples/node/daraja.js`](https://github.com/isaactony/daraja-docs/tree/main/examples/node/daraja.js) flattens this into an object. For failure codes, such as `1` (insufficient balance), `2001` (wrong credential), and `2040` (unregistered customer), see [Result codes](/reference/result-codes).

## Handle timeouts without paying twice

If M-Pesa can't process the request in time, it posts to your `QueueTimeOutURL` instead. A timeout doesn't tell you whether the money moved.

1. Mark the payout `unknown`, not `failed`.
2. Check it with [Transaction Status](/guides/check-a-transaction-status), using your `OriginatorConversationID`.
3. Retry only if the status check shows the payout failed, and use a new `OriginatorConversationID` for the retry. If the status is unclear, check the M-Pesa organization portal first.
