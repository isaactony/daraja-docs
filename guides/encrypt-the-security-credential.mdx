---
title: "Encrypt the security credential"
description: "Generate the SecurityCredential for B2C and Transaction Status by RSA-encrypting the initiator password with M-Pesa's certificate, using PKCS #1 v1.5 padding."
---

B2C, Transaction Status, Account Balance, and Reversal requests need a `SecurityCredential`: your initiator password, encrypted with M-Pesa's public key certificate. For background, see [Initiators and security credentials](/concepts/initiators-and-security-credentials).

## Get the certificate

Download the certificate for your environment from the official [Getting Started](https://developer.safaricom.co.ke/apis/GettingStarted) page, under "M-Pesa API Certificates". There's one for the sandbox and one for production. Save it as a file, such as `certs/sandbox.cer`.

The functions below expect PEM text, which starts with `-----BEGIN CERTIFICATE-----`. If your file is binary, convert it:

```bash
openssl x509 -inform der -in sandbox.cer -out sandbox.pem
```

## Encrypt the password

The algorithm, from the official docs: RSA encryption with the certificate's public key, **PKCS #1 v1.5 padding** (not OAEP), then base64.

<CodeGroup>

```javascript Node.js
// From examples/node/daraja.js
import crypto from 'node:crypto';

export function securityCredential(initiatorPassword, certificatePem) {
  const encrypted = crypto.publicEncrypt(
    { key: certificatePem, padding: crypto.constants.RSA_PKCS1_PADDING },
    Buffer.from(initiatorPassword),
  );
  return encrypted.toString('base64');
}

// Usage
const pem = fs.readFileSync('certs/sandbox.pem', 'utf8');
const credential = securityCredential(process.env.DARAJA_INITIATOR_PASSWORD, pem);
```

```python Python
# From examples/python/daraja.py (needs: pip install cryptography)
def security_credential(initiator_password, certificate_pem):
    from cryptography import x509
    from cryptography.hazmat.primitives import serialization
    from cryptography.hazmat.primitives.asymmetric import padding

    pem = certificate_pem.encode() if isinstance(certificate_pem, str) else certificate_pem
    if b"BEGIN CERTIFICATE" in pem:
        public_key = x509.load_pem_x509_certificate(pem).public_key()
    else:
        public_key = serialization.load_pem_public_key(pem)
    encrypted = public_key.encrypt(initiator_password.encode(), padding.PKCS1v15())
    return base64.b64encode(encrypted).decode()
```

```php PHP
// From examples/php/Daraja.php
public static function securityCredential(string $initiatorPassword, string $certificatePem): string
{
    $key = openssl_pkey_get_public($certificatePem);
    if ($key === false || !openssl_public_encrypt($initiatorPassword, $encrypted, $key, OPENSSL_PKCS1_PADDING)) {
        throw new RuntimeException('Could not encrypt with this certificate: ' . openssl_error_string());
    }
    return base64_encode($encrypted);
}
```

```bash OpenSSL
printf '%s' "$DARAJA_INITIATOR_PASSWORD" \
  | openssl pkeyutl -encrypt -certin -inkey sandbox.pem -pkeyopt rsa_padding_mode:pkcs1 \
  | base64 | tr -d '\n'
```

</CodeGroup>

Each version was tested with a 2048-bit X.509 certificate in PEM format: the password was encrypted, then decrypted again with the matching private key. They weren't tested with Safaricom's own certificate.

## Check your result

- **It changes every time.** PKCS #1 v1.5 adds random padding, so the same password gives a different credential each run. That's expected.
- **It's long.** A 2048-bit certificate gives a 344-character base64 string.
- **Encrypt the plain password.** The official Getting Started page says in one place that the password is base64-encoded before encryption, but its step-by-step algorithm encrypts the password bytes directly. These examples follow the steps.

You can also generate the credential with the **Generate Security Credential** tool under **Test Credentials** in the Daraja dashboard. Because each run gives a different string, you can't compare the strings directly; instead, check that requests using your code's output succeed.

## Store it safely

The credential is as sensitive as the password. Generate it at startup or once per deploy from secrets, or store it as a secret itself. Never commit it.

If B2C returns `2001` "The initiator information is invalid", see [the fix](/troubleshooting/initiator-information-is-invalid).
