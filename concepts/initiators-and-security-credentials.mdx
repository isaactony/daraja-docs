title: "Initiators and security credentials"
description: "Understand the initiator (API operator) and the encrypted SecurityCredential that B2C, Transaction Status, Account Balance, and Reversal requests need."
---

STK Push and C2B identify your business with a shortcode and passkey. APIs that move money out of your account or reveal its details need more: an **initiator**, which is a named API user, and that user's password encrypted as a **security credential**.

## Which APIs need them

| API | Needs initiator and `SecurityCredential` |
| :-- | :-- |
| Authorization, STK Push, STK Query, C2B | No |
| B2C | Yes (`InitiatorName`) |
| Transaction Status | Yes (`Initiator`) |
| Account Balance, Reversal, B2B | Yes |

Note that the field is `InitiatorName` in B2C and `Initiator` in Transaction Status.

## The initiator

The initiator is an API operator user on the M-Pesa organization portal, created by your business administrator.

- **Sandbox:** the shared test initiator is `testapi`. Its password is under **Test Credentials** in the Daraja dashboard.
- **Production:** your business administrator creates the user on the M-Pesa organization portal and assigns it the API role for each product, such as the B2C API initiator role. Without the role, B2C returns result code `21`.

The official B2C page warns that the password should use only certain special characters, such as `#`, `&`, `%`, and `$`. Other characters, including `(` and `)`, may be rejected.

## The security credential

You never send the initiator password itself. You encrypt it with M-Pesa's public key certificate:

1. Take the initiator password as bytes.
2. Encrypt them with RSA, using the M-Pesa public key certificate for your environment, with **PKCS #1 v1.5 padding**, not OAEP.
3. Base64-encode the result. That string is the `SecurityCredential`.

Use the sandbox certificate in the sandbox and the production certificate in production. Both are linked from the official [Getting Started](https://developer.safaricom.co.ke/apis/GettingStarted) page.

RSA with PKCS #1 v1.5 padding includes random bytes, so encrypting the same password twice gives two different strings. Both are valid.

For code in Node.js, Python, and PHP, see [Encrypt the security credential](/guides/encrypt-the-security-credential).

## When it's wrong

A wrong initiator name, a wrong password, the wrong certificate, or the wrong padding all give the same result, `2001` "The initiator information is invalid." It arrives in the result callback, not in the immediate response. See [Fix "The initiator information is invalid"](/troubleshooting/initiator-information-is-invalid).

If the API user's password is locked, requests return `8006` "The security credential is locked". The official B2C page says your business administrator can unlock it.
